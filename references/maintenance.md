# 方法库维护

适用于从方案、方法资料或已记录候选中提取方法，以及增补或修订现有库。原始材料、候选和库中正式方法分开保存；只有获批的完整对象进入目标库。

```text
读取与定位材料 → 提取与整理方法 → 对照已有库 → 人工审阅变更 → 安装与验证
```

`<Run>` 是本次维护工作目录；`<Wiki>` 是明确的目标库。目标不清楚且会影响新建或增补时才询问。随 Skill 发布的 `base-wiki` 是只读默认资产；用户库写入用户指定的可写目录，基础库升级在 Skill 源目录完成并走发布流程。

## 1. 读取与定位材料

使用对应文件能力阅读原始内容和图文关系。已有可靠的页码、章节或内容锚点时直接复用；需要分页副本时使用工具接口中的「材料准备」。语义切分服务于完整理解，可以跨页，也可以省略无方法价值的内容。

读取 `planners-source-index`。上游已提供覆盖本批材料的索引时沿用其原路径；未提供时在维护工作区建立一份索引，随阅读更新。校验命令和字段服从该 Skill 的唯一契约，保留实际阅读盲区。

每个方法的来源必须能够解析到来源条目与具体位置。既有 `source_module_instance_ids` 的使用同时保留其映射，不能只留下无法回查的 ID。先记录材料中的观察与推导，再对照旧库措辞。

## 2. 提取与整理方法

Lens 写清解决的问题、所需输入、关键操作、输出、适用与跳过条件、失败方式和边界。每个关键操作应说明使用什么输入、作什么判断，以及怎样影响后续输出；操作数量服从方法本身。

去项目化是把一次性答案改成变量、判断关系和输出要求。品牌名、策略答案、预算等项目填充值留在来源或案例里；真正影响适用性的品类、渠道或领域条件保留在方法边界中。

检查方法是否只是主题标签或「分析资料、形成洞察、输出策略」的空壳。抽不出稳定操作时记录案例价值、证据不足或无可复用方法，可以得到零条候选。

横向整理本轮发现：同一核心方法合并来源，独立问题拆开，核心相同但适用条件或操作分支稳定不同的定义为变体。Lens 与 Recipe 可以往返整理；Recipe 只保留成立的输入输出依赖，而不是把原方案章节换个名字。

有表达价值时添加页面建议，说明论证目的、证据需要、信息关系及承接；不要求固定页数，也不把每个操作机械转换成一页。方法操作与主要输出应有可解释的表达去向。

## 3. 对照并形成变更提案

增补时读取已有对象全文，对比解决的问题、关键操作、输入输出、适用边界和表达结构。Module 与名称只作检索线索；可能跨分类的同类方法也要比较。新建库不做虚构的既有目标匹配。

为候选提出新增、合并、变体、修订、补来源、改归属或无变化建议，给出目标及具体依据。不确定的差异交给人工判断。

将最终候选与变更建议维护在唯一的 `<Run>/change-set.json`。它包含完整拟安装对象、来源映射、目标库路径与基线指纹、既有目标及比较依据；具体字段由对应契约定义。中间阅读笔记不成为第二份正式对象。

Recipe 明确引用本轮候选或已有 Lens；涉及合并或改 ID 时记录最终解析关系。模块归属变化、关联 Recipe 修订和必要的索引变更一并纳入提案，避免只改局部对象留下失效引用。

## 4. 人工审阅与返修

读取 `planners-review-core`，使用本 Skill 的方法库 adapter 生成审阅面。Adapter 将同一份变更提案投影为审阅包，展示完整方法、可回查来源、既有目标全文、具体差异与建议；公共 Skill 负责桥、提交传输和宿主。

按工具接口的「审阅」启动并检查回执。宿主提供 `review_open` 时交给宿主打开，否则使用公共本地宿主；如实报告打开失败并保留可用 URL。等待用户提交时结束当前回合。

用户返回后先收件，检查是否为当前审阅包的实际提交，再校验逐项决定。只有整体意见时读取收据并带回返修，不把它转换成批准，也不读取遗留的逐项批准记录。

按意见修改同一份变更提案，内容改变后生成新审阅包并重新批准。合并或修订安装的是获批的完整最终对象；用户在审阅面直接编辑并批准的最终对象由 adapter 保存在反馈中，不由安装器重新推导。

批准记录绑定审阅包指纹和确切最终内容。需要目标的决定必须指定有效对象。Recipe 只能批准实际执行所需依赖均获准且已有明确去向的版本；可选 Lens 不采用时，最终步骤中也要移除相应依赖。

## 5. 安装与验证

先执行安装预检，确认当前目标库与审阅时的基线一致、批准内容有效、来源可回查且最终引用图完整。目标库已改变时保留当前提案，重新比较受影响对象并审阅；安装器返回冲突，不覆盖新库。

安装器只执行获批变更，排除拒绝、暂缓和未处置项。存在未处置项时可以继续审阅；用户明确要求只安装已批准部分时，按批准子集预检，检查其依赖闭合后安装，不替其余项目补决定。

安装前备份，失败恢复本次覆盖的文件。成功更新 Module、统一 Recipe 目录、索引与 revision，返回 `<Run>/install-report.json`；报告绑定本轮批准内容及前后库指纹，同一批准重复执行返回已安装结果。

把本轮必要的来源定位、方法来源 ID 映射和安装依据保存在库的 revision 溯源记录中。仅归档获授权的来源片段；客户资料和项目文件不默认进入公开发布资产。来源索引仍由原项目或维护工作区维护，revision 是只读溯源记录。

通过结构、索引和引用校验只能说明安装有效。用真实问题检验方法是否补充了判断或表达、是否造成锚定或套模板；对比时保持同一组项目事实，区分真正改变与换说法。没有合适输入时记录待验证，不宣称已经证明效用。

维护交付说明目标库、获批并安装的对象、来源边界、未收录项及验证结果。零候选或全部拒绝时可以以无变更结束，不为完成流程安装占位对象。
